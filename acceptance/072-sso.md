# SSO — Acceptance Criteria

Enterprise single sign-on: configuring a SAML identity provider for a tenant,
the entitlement and permission gates around that configuration, and how a
member's login behaves once SSO is set up.

Each criterion below carries a stable id. The test that proves a criterion
cites its id in a comment above the test, and
`scripts/ci/check-acceptance-coverage.mjs` enforces the join in both
directions — a criterion no test proves fails the build, and so does a test
citing a criterion that no longer exists.

Ids are written, never derived from position: a positional id silently
re-points at a different criterion the moment a scenario is inserted or
reordered, and the test keeps passing while proving the wrong thing. Never
renumber an id. Retire one by deleting the line and the citation together.

## Configuring SSO

1. `AC-072-01` **Given** a tenant entitled to SSO, **When** an admin saves a metadata URL and allowed domains, **Then** a SAML identity provider is created (or updated) and the tenant's SSO configuration is stored.
2. `AC-072-02` **Given** a tenant not entitled to SSO, **When** an admin attempts to save, toggle, test, or delete an SSO configuration, **Then** the operation is denied with a message naming the plan SSO requires.
3. `AC-072-03` **Given** SSO write and delete server actions, **When** called, **Then** each requires its own permission (`sso_config.update` for writes, the owner-only `sso_config.delete` for deletion) independent of the entitlement check, so an unauthorized caller is denied before the service runs.

## Losing entitlement

4. `AC-072-04` **Given** a tenant's SSO configuration is active and enforced, **When** the tenant is downgraded off the entitled plan, **Then** SSO automatically deactivates and enforcement clears — the configuration data is preserved, but sign-in is no longer gated behind a plan the tenant no longer holds.

## Diagnostics

5. `AC-072-05` **Given** an admin tests the SSO connection, **When** the identity provider's metadata is unreachable, malformed, missing required SAML descriptors, or missing a signing certificate, **Then** diagnostics report the specific failure without leaking response details beyond the numeric status.

## Login behavior

6. `AC-072-06` **Given** a domain with an active, enforced SSO configuration, **When** the login flow checks that domain pre-authentication, **Then** it reports SSO is available and enforced for that domain.
7. `AC-072-07` **Given** a user authenticates through the configured identity provider, **When** login succeeds, **Then** an SSO identity record links the user to the tenant's SSO configuration, and the event is recorded in the SSO audit trail.
8. **Given** a domain with SSO enforcement enabled, **When** a user with an email in that domain attempts to sign in with a password instead, **Then** they are redirected to SSO rather than allowed to authenticate with a password.
